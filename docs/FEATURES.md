## 배경 및 문제 정의

지자체 일자리창출과는 매달 약 60개 부서의 자료를 모아 인건비를 계산하고 4대보험을 대조합니다. 현재 이 일에 **월 약 5일**(인건비 4일 + 4대보험 1일)이 걸립니다. 목표는 **월 1일 이내**입니다 ([NFR-03](#5-비기능-요구사항-nfr-01--nfr-18)).

| 기존 행정 업무의 한계 | 본 플랫폼의 해결책 |
| :--- | :--- |
| **60여 개 부서의 제각각 엑셀 서식과 수기 취합**<br>열 순서, 날짜 표기, 셀 병합이 달라 복사·붙여넣기로 야근 발생 | **부서 공통 제출 포털 + 엑셀 표준화 엔진** (FN-09, FN-02)<br>부서가 표준 화면에 직접 제출하고, 어려운 경우에만 엑셀을 표준 스키마로 정규화. 원본 위치 보존 |
| **복잡한 인건비 수작업 계산 및 오차**<br>조퇴, 휴가, 중도 입·퇴사 정산 시 수식 오류 | **결정론적 계산 엔진** (FN-03, FN-14)<br>Decimal 연산, 항목별 산출 근거 보존, 중도 정산 자동 계산 |
| **4대보험 통합 고지서 분리 곤란**<br>주민번호만으로 찾다가 동명이인·타 사업 귀속 오류 | **다차원 보험 귀속 매칭** (FN-04)<br>식별정보 + 사업장 + 귀속기간 + 배치이력 교차 대조, 퇴사자 환급 추적 |
| **종이 출석부 육안 전수 대조**<br>수기 출석부와 엑셀 근무시간을 일일이 비교 | **전자출석 + 스캔 출석부 OCR 대조** (FN-12, FN-06)<br>담당자가 모바일로 바로 입력하고, 남은 종이 출석부는 OCR로 엑셀과 1:1 대조 |
| **기관별로 다른 제출 양식**<br>건강보험공단·일모아·인사랑 양식마다 재입력 | **기관별 제출 양식 Export** (FN-07, FN-16)<br>검증된 단일 데이터로 5종 양식 자동 생성 |
| **제출 독촉·승인·계좌 변경 확인을 전화·공문으로 처리** | **승인·변경 감지·마감 관리** (FN-10, FN-11, FN-15)<br>부서장 승인과 공문 연결, 전월 대비 변경 표시, 자동 독촉 |

## 1. 핵심 기능 (FN-01 ~ FN-08)

### FN-01. 참여자 통합 등록·검색
- **입력**: 기준 명단(이름, 식별정보, 성별), 사업명, 배치 부서, 담당자, 근무 시작일·종료일.
- **처리**:
  - **이력 분리 저장**: 개인(`Person`), 사업 참여(`Participation`), 부서 배치(`PlacementHistory`)를 따로 관리.
  - 재참여와 월중 부서 이동 전후의 소속·기간 이력을 보존.
  - "기준일 현재 재직자"와 "특정 월 근무 대상자"를 각각 필터링.
- **출력**: 조건별(사업/부서/월/상태) 명단 조회, 개인별 이동·퇴사·과거 정산 통합 이력.

### FN-02. 부서별 엑셀 자동 취합
> FN-09(부서 공통 제출 포털)로 제출하기 어려운 경우의 **보조 경로**입니다.

- **입력**: 약 60개 부서별 월별 엑셀 파일, 자료 종류, 사업, 부서, 업무월.
- **처리**:
  - 양식별 열 이름·날짜·금액을 표준으로 매핑. **식별자는 문자열로 처리**(앞자리 0 보존).
  - 합계·설명 행과 실제 참여자 데이터 행을 자동 구분.
  - 원본 **파일·시트·행 번호**를 보존하고, 같은 파일을 다시 올려도 중복 반영하지 않음.
- **출력**: 월별 표준 통합 목록, 누락·중복·형식 오류 내역, DB 최종 반영 전 미리보기 화면.

### FN-03. 월별 인건비 계산·집계
- **입력**: 적용 단가, 근무일·시간, 조퇴 내역, 승인된 유·무급 휴가/공휴일 기준, 중도 입·퇴사일, 확인된 공제액.
- **처리**:
  - 엑셀에 저장된 수식값에 의존하지 않고 **서버에서 십진수(`Decimal`)로 직접 검산** (T2, T3).
  - **총 지급액** = 기본 근무급 + 승인된 유급휴가·주휴·연차 미사용 정산액
  - **실지급액** = 총 지급액 − 확인된 근로자 부담 공제액 (**기관 부담금은 별도 분리**)
- **출력**: 개인별 지급·공제 항목 상세와 계산 근거, 휴가 발생·사용·잔여·정산 내역, 부서·사업·월별 총괄 집계표와 지급 상태.

### FN-04. 4대보험 귀속·납부·환급
- **입력**: 공단 부과·정산·환급 원본 엑셀, 보험 종류, 부과월, 귀속기간, 금액.
- **처리**:
  - **주민번호 단독 매칭 금지** → 식별정보 + 사업장 + 귀속기간 + 배치이력을 교차 대조.
  - 동일인의 타 사업 부과분과 퇴사자의 과거 귀속 환급분을 분리 추출.
  - 귀속 근거가 명확한 행만 급여 공제에 자동 연결하고, 불명확한 행은 후보를 비교해 보여줌.
- **출력**: 해당 사업 대상 보험 내역 추출본, 귀속 불명확 확인 대상 목록, 미납·미환급(퇴사자 포함) 관리 현황.

### FN-05. 제출자료 누락·오류 검증
- **입력**: 취합된 엑셀 데이터, 서버 인건비 계산값, 보험 매칭값.
- **처리**:
  - 필수값 누락, 기준 명단 불일치, 중복 반영, 참여 기간 외 근무기록을 자동 검출.
  - 부서 제출 금액과 시스템 계산 금액의 차액 검증.
  - 항목을 수정하거나 확인 사유를 입력하면 관련 검사와 전체 합계를 **즉시 재실행**.
- **출력**: 오류 리포트(대상자 / 항목 / 입력값 / 기준값 / 차이 / 원본 위치 / 해결 상태), 수정 이력과 처리자 근거 기록.

### FN-06. 스캔 출석부·엑셀 비교
- **입력**: 스캔 출석부(PDF·이미지), 해당 월 부서 인건비 엑셀.
- **처리**:
  - 이미지 기울기·잡음 보정(**OpenCV**) 후 한국어·숫자 문자 인식(**PaddleOCR**)을 **비동기**로 처리. 서버 내부(온프레미스)에서만 처리 (NFR-08).
  - 추출한 성명·날짜·근무/조퇴/휴가 내역을 엑셀 입력값과 1:1 자동 대조.
  - 원본 스캔본과 추출값을 나란히 놓고, 선택한 항목의 원본 위치를 하이라이트.
  - 인식 신뢰도만으로 자동 확정하지 않음 (T4).
- **출력**: 일치 / 불일치 / 미판독 분류 결과, 좌우 대조 검토 및 수동 보정 화면.

### FN-07. 기관별 제출 양식 Export
- **입력**: 검증·확정된 월별 인건비 데이터, 확정된 4대보험 및 참여자 이력.
- **처리**:
  - 제출 대상 기관별 지정 포맷(열 순서, 필수값, 날짜·금액·코드 형식) 자동 매핑. 포맷은 코드가 아니라 **설정**으로 관리 (NFR-16).
  - 다운로드 전 필수값 누락 여부와 **개인별 합계 ↔ 총괄표 합계** 일치 검사.
  - 생성한 파일 이력과 출력 시점의 데이터 기준을 기록·보존.
- **출력**: 기관별 맞춤형 제출용 엑셀 파일 5종 → [EX-01 ~ EX-05](#2-제출-양식-export-상세-ex-01--ex-05)

### FN-08. 담당 업무·마감 알림
- **입력**: 사업·업무월·기준일별 처리 상태, 기관별 신고·지급 마감 일정 기준.
- **처리**:
  - **완료 상태 엄격 분리**: `계산 완료` ≠ `파일 생성` ≠ `급여 지급` ≠ `보험 납부` ≠ `외부 신고`. 각각 독립 상태로 관리하고, 파일만 생성했다고 완료 처리하지 않음.
  - 현황 카드를 누르면 해당 조건의 미처리 대상자 목록으로 바로 이동(드릴다운).
- **출력**: 선발/현재/퇴사 인원 및 예산 집행 대시보드, 미처리 급여·보험·환급·신고 목록, 기한 임박·초과 업무 **웹 알림**(외부 메일 미사용, NFR-05).

## 2. 제출 양식 Export 상세 (EX-01 ~ EX-05)

FN-07의 세부 규격입니다. 검증이 끝난 **단일 데이터**로 수작업 재입력 없이 외부 기관·내부 보고용 서식을 만듭니다.

| 구분 | 제출 대상 | 양식 | 주요 항목 및 변환 규칙 | 사전 검증 및 출력 조건 |

## 3. 공통 데이터 처리·권한 규칙

모든 기능에 반드시 적용합니다.

- **권한별 접근 제어**: 내부 관리자는 전체 사업을 조회·출력할 수 있고, 사업 담당자는 허용된 사업의 데이터만 조회·수정·다운로드합니다. 이 차단은 **서버 API 단**에서 합니다 (NFR-09).

## 4. 확장 기능 (FN-09 ~ FN-16)

약 60개 부서가 **공통 플랫폼에 직접 제출**하고, 담당 공무원이 **모바일로 전자출석**을 입력할 수 있다는 가정에서 추가한 기능입니다. FN-02(엑셀 자동 취합)는 플랫폼 제출이 어려운 경우의 보조 경로로 유지합니다.

### FN-09. 부서 공통 제출 포털
- **입력**: 부서 담당자 계정(약 60개 부서), 업무월, 사업명, 웹 입력값 또는 표준 엑셀 업로드 파일.
- **처리**:
  - **직접 제출**: 부서 담당자가 공통 웹 화면에서 직접 입력하거나 표준 양식을 업로드.
  - **입력 형식 강제**: 날짜(`2026-01-01`, `260101`, `0101` 등)와 금액을 입력 즉시 표준 형식으로 정규화.
  - **양식 변조 차단**: 열 구조를 임의로 바꾼 파일은 업로드를 거부하고 수정 위치를 안내.
  - **식별번호 검증**: 주민등록번호는 형식·체크섬만 검증 (본인 일치 여부는 확인 불가).
  - **버전 관리**: 임시저장·제출·재제출을 구분하고 제출본별 버전을 보존.
- **출력**: 부서별 제출 접수 현황, 제출본 버전 목록, 항목별 입력 오류 안내.

### FN-10. 부서장 승인·공문 연계
- **입력**: 부서 제출본, 부서장 계정, 공문 번호 또는 공문 첨부 파일.
- **처리**:
  - **승인 절차**: 부서장이 승인해야만 제출이 확정. 반려 시 사유 필수 입력.
  - **공문 연결**: 공문 번호·첨부로 제출본과 공문을 연결해, 공문과 자료를 이중으로 요청하지 않음.
  - **확정 후 잠금**: 확정된 제출본은 직접 수정 불가. 재제출·재승인으로만 변경.
- **출력**: 승인 상태(`작성 중` / `제출` / `승인` / `반려`), 반려 사유와 공문 연결 정보.

### FN-11. 전월 대비 변경 항목 표시
- **입력**: 당월 제출본, 전월 확정 데이터.
- **처리**:
  - **변경 하이라이트**: 계좌번호, 계약 근무시간(4·5·6시간), 단가, 소속, 근무 기간이 전월과 다르면 셀 단위로 표시.
  - **계좌 변경 잠금**: 계좌가 바뀐 참여자는 관리자 확인 전까지 지급 확정을 막음 (기존 계좌 오지급 방지).
  - **변경 기록**: 변경 전후 값과 입력자를 기록.
- **출력**: 전월 대비 변경 목록, 계좌 변경 대상자와 확인 상태.

### FN-12. 담당자 모바일 출결 입력
- **입력**: 담당 공무원 모바일 브라우저, 근로자, 일자, 출근/조퇴(시간)/연차/결근 구분.
- **처리**:
  - **담당자 대리 입력**: 근로자 개인 기기 불필요 (휴대폰 미소지·일반폰 근로자 고려).
  - **설치 없는 모바일 웹**: 반응형 웹 또는 PWA로 동작하며 입력 즉시 서버로 전송.
  - **인정 시간 자동 계산**: 근로자별 계약 근무시간(4·5·6시간) 기준.
  - **일수·시간 분리**: 조퇴는 시간으로 저장하되 근무일수는 따로 집계 (조퇴일도 1일로 계산).
  - **마감 후 수정**: 사유 필수 입력, 변경 이력 보존.
- **출력**: 일별·월별 전자 출석부, 근무일수·조퇴시간·연차 사용 집계.

### FN-13. 월말 확인서·청구서 서명
- **입력**: 월 확정 출석 데이터, 월 인건비 산출 결과.
- **처리**:
  - **서식 자동 생성**: 월말 출석 확인서·인건비 청구서 PDF 생성.
  - **본인 확인**: 담당자 단말 전자서명, 또는 출력본에 서명·도장 후 스캔 업로드 중 선택.
  - **금액 변경 대응**: 산출 금액이 바뀌면 청구서 새 버전을 만들고, 이전 서명본은 무효 처리 후 재서명 요청.
  - **증빙 보관**: 서명본·스캔본을 제출본과 연결해 보관.
- **출력**: 출석 확인서·청구서 PDF, 서명 완료 여부와 재서명 필요 목록.

### FN-14. 중도 입·퇴사 자동 정산
- **입력**: 입사일, 퇴사일·사유, 마지막 근무일, 근로자별 계약 근무시간·단가.
- **처리**:
  - **퇴사 정산 자동 계산**: 마지막 근무일을 입력하면 일할 근무급, 미지급 주휴수당, 미사용 연차수당 산출.
  - **연차 규칙**: 한 달 만근마다 1일 발생, 퇴사 시 미사용분 정산, 누락 시 경고.
  - **상실 신고 선반영**: 퇴사 월 급여 지급 전에 예상 보수액을 산출해 [EX-02](#2-제출-양식-export-상세-ex-01--ex-05)에 연결.
  - **대체 투입 이력**: 중간 입사자·대체 투입자의 근무 기간 관리.
- **출력**: 개인별 중도 정산 내역과 계산 근거, 상실 신고용 예상 보수액, 연차 정산 누락 경고.

### FN-15. 제출 독촉·마감 관리
- **입력**: 월별 일정(요청일, 마감일, 최종 독촉일, 지급일), 부서별 제출·승인 상태.
- **처리**:
  - **일정 설정**: 예) 24일 요청 → 29일 마감 → 30일 최종 독촉 → 익월 1일 지급.
  - **자동 독촉**: 미제출·미승인·반려 부서 담당자에게 웹 알림을 반복 발송.
  - **대리 제출**: 담당자 부재 시 대리 제출자 지정.
- **출력**: 부서별 제출 현황판(`미제출` / `제출` / `승인` / `반려` / `지연`), 지연 부서 목록과 독촉 이력.

### FN-16. 일모아·인사랑 일괄 등록 지원
- **입력**: 확정된 참여자·급여 데이터.
- **처리**:
  - **일괄 등록 파일**: 일괄 등록 가능 항목(이름, 주민번호, 고용 시작일, 휴대폰)은 업로드 파일 자동 생성.
  - **수기 입력 지원**: 직종, 사업명, 비고(주당 근무시간) 등 일괄 등록이 안 되는 항목은 체크리스트 제공.
  - **월별 대상 구분**: 신규 등록·퇴사 처리 대상을 나눠 표시.
- **출력**: 일괄 등록용 엑셀 파일, 수기 입력 체크리스트.
- 일모아·인사랑은 외부 API 연계가 불가능하므로, 파일 생성과 체크리스트 제공까지만 범위로 합니다.

## 6. 가정 및 확인 필요 사항

캡스톤 범위에서 둔 가정입니다. 아키텍처 관점의 전제는 [ARCHITECTURE.md 13장](ARCHITECTURE.md#13-전제-가정)에 있습니다.

- **캡스톤 가정**: 회의에서 현행 제약으로 어렵다고 한 공통 플랫폼 직접 제출(FN-09)과 전자출석(FN-12)을 구현 가능으로 가정합니다. 실제 도입 시 행정망 환경과 공문 결재 절차에 맞는지 확인이 필요합니다.
- **전자서명 효력**: 근로자 전자서명의 증빙 효력은 담당 부서 확인이 필요합니다. 확인 전까지는 출력본 서명 후 스캔 업로드 방식을 함께 지원합니다 (FN-13).
- **외부 시스템 연계**: 일모아·인사랑은 외부 API 연계가 불가능하므로, 일괄 등록용 파일 생성과 수기 입력 체크리스트 제공까지만 범위로 합니다 (FN-16).
- **수치 기준**: NFR의 응답 시간, 가용률, 보존 기간 등 수치는 제안값이며 담당 부서와 협의해 확정합니다.
- **개인정보**: 개인정보가 저장된 서버에는 접근할 수 없으므로, 개발과 시연은 가상 데이터로 진행합니다.
